# HypoWeaver 用户全流程与分阶段实施清单

## 1. 产品目标

HypoWeaver 不是单纯的论文搜索工具，也不是只接收结构化案例的统计执行器。完整产品应把两条链路连成一条用户旅程：

1. 数据中心持续汇集论文、政策、数据目录与研究方法，完成去重、清洗、来源绑定、向量索引和知识图谱构建；
2. 用户围绕一个研究主题检索证据，识别趋势与研究空白，生成可证伪假设和“科学十项”Proposal，再进入 H1–H4 的正式研究执行、审查与交付。

数据中心是底座；“从问题到成果”的研究项目才是用户实际购买和使用的产品。

## 2. 用户应看到的完整旅程

### 阶段 1：提出研究主题

用户在“新研究”中输入一个主题、问题或现实观察，也可以补充自己的论文、政策材料和数据。

系统输出：

- 规范化研究主题；
- 关键词、相关构念与初始边界；
- 本次研究项目及可回看的进度页。

### 阶段 2：自动检索数据中心

系统同时检索论文、政策、数据目录和方法库，并在必要时使用用户上传的原始 PDF。

检索方式包括：

- 关键词与结构化字段检索；
- 向量语义检索；
- 图谱邻居与关系扩展；
- 时间、来源、研究对象、方法和证据等级过滤。

所有命中都进入项目 EvidenceBundle，保留来源、定位信息、哈希和访问边界。

### 阶段 3：形成研究趋势图

系统把海量命中压缩成用户能判断的研究地图：

- 主题簇和时间演化；
- 主要理论、变量和方法；
- 已有共识与相互冲突的结论；
- 最新热点和正在增长的研究方向；
- 证据覆盖不足或数据可得性不足的区域。

### 阶段 4：识别研究空白

系统生成受 EvidenceBundle 约束的 GapCard，而不是泛泛描述“研究不足”。每张 GapCard 至少包含：

- 已知证据；
- 尚未回答的问题；
- 空白成立的语料边界；
- 可能的理论或实证贡献；
- 需要补充的证据与风险。

用户在 H0 选择、合并、修改或拒绝研究空白。

### 阶段 5：生成候选研究假设

系统围绕用户批准的 GapCard 生成多组 HypothesisCard，包括：

- 假设陈述和预期方向；
- 理论机制与竞争机制；
- 自变量、因变量、调节/中介变量；
- 可证伪预测；
- 建议研究对象、数据和识别策略；
- 与现有研究的差异及证据引用。

用户比较后选择一组假设进入 Proposal。

### 阶段 6：生成“科学十项”Proposal

现有仓库已经定义并能在特定 Group1 交接路径中生成以下十项，但普通用户主流程尚未接入：

1. 研究问题与项目定位；
2. 研究空白与贡献边界；
3. 核心假设与可证伪预测；
4. 竞争机制与理论路径；
5. 研究对象、处理与边界条件；
6. 变量操作化与测量口径；
7. 数据、授权与连接可行性；
8. 识别策略与方法实现；
9. 诊断、稳健性与停止规则；
10. 阶段产物、Go/No-Go 与主张边界。

每项应显示“证据已绑定 / 有条件 / 待补充”，列出引用和未解决行动。用户可以逐项修改、确认，再创建正式研究任务。

### 阶段 7：H1–H4 正式研究

- H1：确认研究问题、假设、变量、样本和时间边界；
- H2：比较并冻结识别策略、数据与诊断方案；
- 执行：运行统计分析并由独立执行路径复现；
- H3：逐条审查主张，只允许证据支持的结论；
- H4：审核论文或报告，完成来源绑定与封存。

### 阶段 8：成果与持续研究

项目最终提供：

- 趋势与空白报告；
- GapCard、HypothesisCard 和科学十项 Proposal；
- 冻结研究方案、代码、图表与复现记录；
- 获准结论、失败/不足说明和最终论文或报告；
- 后续新增论文或政策与当前项目的差异提醒。

## 4. 分阶段实施顺序

### 工作 1：清理文献库信息架构

- 移除“目录线索”演示入口；
- 文献库只保留“系统论文库”和“我的原始 PDF”。

状态：已完成。

### 工作 2：打通“新研究 → 自动发现”入口

- 用户输入主题后自动创建项目；
- 展示检索、趋势、空白、假设、科学十项、正式研究和交付的全流程进度；
- 不再让用户自己猜应该先去资源库还是项目页。

验收标准：输入一个主题即可进入项目，并看到系统开始检索数据中心。

### 工作 3：建立真实项目 EvidenceBundle

- 系统论文、政策、数据、方法和用户 PDF 都能加入项目；
- 每项资源显示来源、可用边界和引用状态；
- 移除旧前端演示资源对正式流程的依赖。

### 工作 4：交付趋势与研究空白

- 生成主题趋势、结论冲突、方法演化和证据缺口；
- 生成可审阅 GapCard；
- 增加 H0 人工选择。

### 工作 5：交付候选假设

- 从已批准 GapCard 生成多组 HypothesisCard；
- 支持比较、编辑、拒绝和选择；
- 明确变量、机制和证伪路径。

### 工作 6：把科学十项接入普通项目

- 从所选假设自动编译十项 Proposal；
- 提供逐项状态、引用、缺口和编辑确认；
- 十项通过后才能创建 H1 正式任务。

### 工作 7：打通 H1–H4 与成果页

- 将 Proposal、EvidenceBundle 和用户确认完整带入正式任务；
- 在项目页统一展示执行、复现、主张审核和最终成果；
- 明确区分“工程执行成功”和“科学结论获支持”。

## 5. 下一项工作

下一项应先实现“工作 2：打通新研究入口到自动发现”。只有入口与项目主流程稳定后，EvidenceBundle、GapCard、HypothesisCard 和科学十项才有清晰的用户承载位置。
