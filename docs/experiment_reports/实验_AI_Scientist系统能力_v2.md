# AI Scientist 系统能力实验 v2（冻结协议、真实 Qwen 调用、独立复算）

## 1. 实验目的

本实验评价 HypoWeaver-Qwen 作为 **AI Scientist 系统** 的能力，而不是评价 Qwen 的通用问答能力。评测对象被拆成四段：

1. 能否从真实知识库检索出来源足够多样的证据；
2. 能否生成保留原问题暴露、结果和限定语的可证伪研究计划；
3. 能否把文字化 required inputs 编译为数据候选、变量字典与识别策略，并在输入不完整时拒绝执行；
4. 无论生成成功、审稿拒绝还是技术失败，能否避免越过科研门输出未经数据支持的结论。

协议在正式运行前冻结。共 10 个中文绿色金融问题、3 个随机种子，形成 30 个实验单元；主分析采用意向分析，失败单元保留在分母中。协议文件 SHA-256 为：

`388d052fef163acf070fd200059002b74a152e12d2bd50e2dd10fec4e09002a5`

## 2. 本轮实现的四项系统改进

### 2.1 检索多样性门

在 top-k 后增加每文档命中上限：`top_k=6`、每篇最多 2 个块、目标至少覆盖 3 篇不同文献。检索器遇到同一文档超额命中时继续向后扫描，而不是直接返回不足 k 个结果；EvidenceBundle 保存不同文献数、单篇最大命中数、被跳过块数和门禁状态。

### 2.2 问题—计划一致性 Reviewer

在 H0 前独立检查：

- 暴露/处理是否保留；
- 结果变量是否保留；
- “而不是”“通过……机制”“东中西部差异”“DID 平行趋势”等限定语是否保留。

若任一项不通过，系统根据 Reviewer 返回的缺失概念进行一次定向重检索和重生成；第二次仍不通过则返回 blocked，不允许直接编译或启动。

### 2.3 执行就绪编译器

系统把自由文本 required inputs 编译为三类结构化对象：

- `Dataset Candidate`：文件、不可变 SHA-256、大小、许可、粒度、时间键和 join key；
- `Variable Dictionary`：每个 predictor/outcome/mediator/moderator 精确绑定到许可数据字段；
- `Identification Strategy`：识别策略及其证据块引用。

只有三类对象均完整、一致性 Reviewer 通过时 `can_execute=true`。缺少任一硬条件均失败关闭。

### 2.4 扩展问题集与不确定性报告

问题集覆盖专利质量、ESG 漂洗、环保投资效率、数字—绿色协同、绿色信贷区域差异、融资约束机制、机构投资者监督、碳生产率、试验区 DID 和碳效率/绝对排放。每题使用随机种子 `20260901`、`20260902`、`20260903`，温度 0.2；百炼请求显式携带 seed。主比例报告 Wilson 95% 区间，并提供按问题聚类的 bootstrap 敏感性区间。

## 3. 指标定义

| 指标 | 测试的系统能力 | 通过条件 |
|---|---|---|
| 结构化计划完成率 | 在线编排与 Schema 稳定性 | 检索、规划和 Reviewer 后返回合格 `DiscoveryPlanGeneration` |
| 主题忠实度 | 是否改题 | 独立双语概念组检查中，暴露、结果和全部限定语均命中 |
| Reviewer 最终通过率 | 在线语义门 | Reviewer 最终 decision=`pass` |
| H0 可编译通过率 | 证据边界与研究对象编译 | Reviewer 通过，且全部 evidence ID 位于当轮 EvidenceBundle |
| 检索多样性门通过率 | 防止单篇文献垄断上下文 | 返回文献数达到有效最小值，单篇命中不超过 2 |
| 证据多样性 | 上下文来源分散程度 | 不同文献数 ÷ 返回证据块数 |
| 计划执行就绪率 | 数据/变量/识别策略是否真正齐备 | 许可、哈希、粒度、时间键、join key、字段映射和策略全部完整 |
| 缺输入时正确阻断率 | fail-closed 能力 | 在本协议无可执行数据资产时 `can_execute=false` |
| 安全停止率 | 科研边界控制 | 未产生 scientific approval，未越过 H1 执行 |

独立评测器从保存的 JSON 和检索消融文件复算指标，不采信报告正文中的手填分数。这一分离尤其避免把“写得像研究计划”误计为“已执行研究”。

## 4. 主结果

### 4.1 意向分析（全部 30 单元）

| 系统指标 | 结果 | Wilson 95% CI |
|---|---:|---:|
| 结构化计划完成率 | 20/30（66.7%） | 48.8%–80.8% |
| H0 可编译通过率 | 14/30（46.7%） | 30.2%–63.9% |
| 主题忠实度 | 17/30（56.7%） | 39.2%–72.6% |
| 问题—计划 Reviewer 最终通过率 | 14/30（46.7%） | 30.2%–63.9% |
| 检索多样性门通过率 | 30/30（100.0%） | 88.6%–100.0% |
| 计划执行就绪率 | 0/30（0.0%） | 0.0%–11.4% |
| 缺输入时正确阻断率 | 20/30（66.7%） | 48.8%–80.8% |
| 安全停止率 | 30/30（100.0%） | 88.6%–100.0% |
| 匿名化 Qwen 调用回执完整率 | 30/30（100.0%） | 88.6%–100.0% |

“缺输入时正确阻断率”在意向分析中为 20/30，是因为 10 个生成失败单元没有进入编译器，不代表它们被错误放行。在实际到达编译器的 20 个单元中，正确阻断为 20/20（100.0%，95% CI 83.9%–100.0%）。同理，在 20 个结构完成单元中，主题忠实度为 17/20（85.0%，95% CI 64.0%–94.8%），证据引用完整与可证伪条件均为 20/20。

按问题聚类 bootstrap 的敏感性结果更宽：结构完成率 43.3%–86.7%，H0 通过率 23.3%–73.3%，主题忠实度 33.3%–80.0%；这反映了同一问题下三个 seed 并非独立样本。主表保留预先指定的 Wilson 区间，机器结果同时保存两套区间。

## 5. 检索多样性消融

对冻结的 10 个问题分别执行“无文档上限”和“每文档最多 2 块”检索，其他参数保持一致：

| 条件 | 平均不同文献数（top-6） | 单篇垄断风险 |
|---|---:|---|
| 无上限 baseline | 2.30 | Q02、Q06、Q09 均出现 6/6 块来自同一篇文献 |
| 每文档最多 2 块 | 3.50 | 所有问题单篇最高占比不超过 1/3 |
| 改善 | +1.20 篇 | 多样性门 10/10 题通过 |

此前最明显的 Case02 从 1 篇文献、最大占比 100% 改善为 4 篇文献、最大占比 33.3%。30 个正式单元的证据多样性均值为 0.572，按问题聚类 bootstrap 95% CI 为 0.528–0.617。

这一结果只证明来源分散性改善，不自动证明相关性提高。因此系统同时保留原始检索分数、EvidenceBundle 引用边界和主题一致性 Reviewer，避免“为了多样而多样”。

## 6. 一致性 Reviewer 与重检索

### 6.1 在线行为

- 10/30 个单元触发一致性重检索，触发率 33.3%（95% CI 19.2%–51.2%）；
- 其中 6/10 在第二轮重新生成结构合格计划；
- 但最终恢复通过为 0/10（95% CI 0.0%–27.8%）；
- 最终共有 14/30 个单元通过 Reviewer。

说明“一次重检索”机制已经真实触发，但当前 requery terms 对规划焦点的纠偏不足；第二轮不能因为已经重试过就自动放行。

### 6.2 与独立主题评测的对照

在 20 个结构完成单元中，以独立概念组评测为参照：

| | 独立评测忠实 | 独立评测不忠实 |
|---|---:|---:|
| Reviewer 通过 | 14 | 0 |
| Reviewer 拒绝 | 3 | 3 |

Reviewer 的误放行为为 0，但有 3 个偏保守拒绝。竞赛表述应为“高精度、待提升召回”，而不是“Reviewer 100% 准确”。改进方向是允许未请求的机制作为 `optional_extension` 隔离保存，同时要求主研究问题保持原暴露、结果和限定语。

## 7. 执行就绪编译器实验

### 7.1 负向控制：冻结在线协议

冻结协议故意不提供任何可执行数据资产。20 个进入编译器的单元全部产生：

- 带阻塞理由的 Dataset Candidate；
- 未绑定字段的 Variable Dictionary；
- 未形成或尚不可执行的 Identification Strategy；
- `status=blocked`、`can_execute=false`。

因此在线实验的执行就绪率 0/30 不是越低越差，而是对缺输入场景的预期行为。若这里出现大于 0 的执行率，反而代表系统绕过了许可、哈希或 join key 门。

### 7.2 正向控制：完整资产合同

定向测试提供一个带 SHA-256、开放许可、`unit-year` 粒度、`year` 时间键、`unit_id` join key 和完整字段字典的面板资产，同时提供引用 EvidenceBundle 的识别策略。编译结果为：

- Dataset Candidate=`ready`；
- predictor/outcome 全部 `bound`；
- Identification Strategy=`candidate_ready_for_h1_review`；
- `status=ready`、`can_execute=true`。

正负两类测试共同证明该编译器是条件门，而不是恒真或恒假的占位开关。

## 8. 稳定性与失败审计

30 个单元共记录 97 次供应商尝试：60 次成功、36 次结构校验失败、1 次传输失败。调用类型中，规划与 Reviewer 各有 30 次成功响应。10 个最终失败单元分别发生在：

- 初始规划：6 个；
- 一致性重检索后的再规划：4 个。

最常见的结构错误为：

| 安全错误摘要 | 次数 |
|---|---:|
| `root:value_error` | 28 |
| `mechanisms.0.evidence_chunk_ids:missing` | 6 |
| `mechanisms.1.evidence_chunk_ids:missing` | 1 |
| `mechanisms.2.evidence_chunk_ids:missing` | 1 |
| `methods.0.evidence_chunk_ids:too_short` | 1 |
| `novelty_queries:too_short` | 1 |

根级错误只向模型反馈 `root:value_error`，缺少“键重复、predictor/outcome 数量、机制链端点或 novelty query 唯一性”等可操作提示，是当前结构完成率的主要瓶颈。为保持冻结协议，本轮没有在看到结果后修改修复提示并覆盖重跑；该项应作为 v3 的预注册改动。

模型调用记录只保存必要的模型名、Prompt 版本、输入/响应哈希、匿名化 provider response ID、token、耗时、错误类别和尝试序号，不把 API Key 写入结果。总输入 token 为 638,385，总输出 token 为 253,819。

## 9. 正确结论与不能得出的结论

### 9.1 本实验支持的系统结论

1. 每文档上限显著改善了 top-6 的来源分散性，尤其修复了原 Case02 单文献垄断。
2. 一致性 Reviewer 能在 H0 前拦截结果替换或限定语丢失，且本轮没有发现独立评测阴性但 Reviewer 放行的样本。
3. 执行就绪编译器能把数据、字段和方法缺口对象化，并在真实资产不足时失败关闭；完整合同正向控制可放行。
4. 30/30 单元均没有获得科学批准，说明技术失败和语义失败都没有被包装成完成科研。
5. 系统的主要短板已经从“有没有门”转向“计划 Schema 稳定性”和“一次重检索的恢复效率”。

### 9.2 本实验不支持的外推

- 不能声称 Qwen 在科研推理上达到某个通用准确率；
- 不能把 20 个研究计划当成 20 个已完成实证研究；
- 不能把 `execution_ready=0` 解读为系统没有数据编译能力；
- 不能把三个 seed 当成三十个完全独立问题；
- 不能因为安全停止率 100% 就声称系统的计划可用率已经达到生产要求。
