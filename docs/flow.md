# 前端流程设计（已定稿）

> 来源：grill-with-docs 访谈 Q1–Q15（2026-10）。术语见 [GLOSSARY.md](../GLOSSARY.md)，关键取舍见 [ADR 0001](adr/0001-wizard-locked-versions-stale-downstream.md)。
> 可点击原型：`cd frontend && npm run proto:flow`，打开 `/prototype/flow`。

## 1. 面向谁

- 主要用户是**第一次做研究的人**。
- **不做熟手快捷方式**：没有"一键跑到底"，也没有快捷键。整个界面只有一条路，就是跟着主按钮往下走。

## 2. 向导式流程

- 六个阶段依次是：方向 → 文献 → 候选假设 → 研究计划 → 数据与检验 → 提案。
- 还没走到的阶段是锁定的，阶段栏上不能点；已经完成的阶段可以回去查看和编辑。
- 点"编辑"已确认的阶段时，先弹一个确认框："修改后，后面 N 个阶段需要更新"，可以选「继续编辑」或「取消」。
- 修改并确认后，下游阶段都标成**需要更新**（阶段栏显示黄点）。主按钮变成"**更新下一阶段**"，带你按顺序逐个重做；没受影响的内容保留，重做时预先填好。

## 3. 主按钮

- 每个页面只有**一个主按钮**，固定在顶部阶段栏的右侧，文字随状态变化。
- 页面上其它按钮都是次要样式（描边或文字按钮）。

## 4. 草稿与版本

- 所有编辑**自动保存为草稿**，不再有任何"保存"按钮。
- 只有一个动作："**确认并进入下一阶段**"。它锁定当前版本，并解锁下一阶段。
- 之后再编辑已确认的阶段，会生成一个新版本。

## 5. 每个阶段谁来做决定

| 阶段 | 系统做什么 | 你做什么 | 主按钮的变化 |
|---|---|---|---|
| 方向 | — | 填写研究方向 | 确认并进入下一阶段 |
| 文献 | 检索文献 | 勾选证据 | 检索文献 → 去勾选证据 → 确认并进入下一阶段 |
| 候选假设 | 生成候选 | 选一个 | 生成候选假设 → 选择一个候选 → 确认并进入下一阶段 |
| 研究计划 | 起草计划 | 确认 | 起草研究计划 → 确认并进入下一阶段 |
| 数据与检验 | 建议变量绑定、运行检验 | 上传数据、确认绑定 | 上传数据 → 确认数据绑定 → 运行检验 → 确认并进入下一阶段 |
| 提案 | 生成提案 | 确认 | 生成提案 → 确认提案 → 导出 |

系统在工作时显示进度；轮到你操作时，要醒目地提示出来。

## 6. 页面骨架（从上到下）

1. 阶段栏，主按钮在它的右侧。
2. 一行"这里要做什么"。
3. 任务清单（见第 7 节）。
4. 主要工作内容，占满剩下的区域。
5. 参考信息默认折叠，放在侧栏或底部。

## 7. 任务清单

- 放在页头下方，**最多 3 项**，勾选状态跟着实际进度变化。
- 只有一个动作的阶段（例如方向、研究计划）不显示任务清单。

## 8. 进度视图

- 系统需要较长时间的工作（检索、生成、检验）期间，整个工作区换成进度视图：说明正在做什么，以及完成了几项（n/m）。
- 完成后自动切到结果，主按钮变成下一步要做的事，例如"去勾选证据"。

## 9. 引导卡

- 每个阶段第一次进入时，显示一张可以关闭的引导卡，说明这个阶段做什么。
- 关闭后，点页头的"?"可以重新打开。

## 10. 模型未配置或调用失败

- 没有配置模型时，主按钮变成"**去设置模型**"；调用失败时，主按钮变成"**重试**"。旁边写出原因。
- 其它依赖模型的按钮**直接隐藏**，不是置灰。

## 11. 概览

- 最上面是一张大卡片："下一步：阶段 n · 要做什么"，带一个按钮；各阶段的摘要放在下面。
- 打开项目时默认进入概览；如果有阶段正在等你确认，就直接进入那个阶段。

## 12. 提案

- 没有"保存提案"按钮，内容自动保存。
- 主按钮依次是：**生成提案 → 确认提案 → 导出**。
- 某一节生成失败时，在这一节原地显示原因和"**重新生成本节**"按钮。数据来自 `narrative_failures[{section, reason}]`。

## 已删除的设计

- 熟手的"一键跑到底"和 Ctrl+Enter 快捷键（访谈 t16u）。
- 各页的"保存""保存提案"按钮。
- 阶段栏上的自由跳转：只能跳到已完成的阶段。
